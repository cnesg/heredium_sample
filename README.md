# ARTREND

국내외 미술 동향을 한 화면에서 보는 대시보드. 갤러리 17곳의 전시 소식, 국내 경매
낙찰 기록, 아트페어 일정, 뉴스·영상을 모아 "지금 누가·무엇이 움직이는가"를 보여준다.

## 데이터가 오는 세 갈래

Vercel 크론은 클라우드에서 돌기 때문에 로컬에 있는 경매 CSV를 볼 수 없고, Supabase는
크론이 며칠 돌아야 채워진다. 그래서 소스를 성격별로 나눴다.

| 계층 | 무엇 | 자격증명 | 갱신 방법 |
| --- | --- | --- | --- |
| **정적 동봉** | 경매 집계 인덱스(`data/market/`), 페어 캘린더(`lib/fairs.ts`), 시장 리포트 수치(`lib/marketReports.ts`) | 불필요 | 로컬 스크립트 → 커밋 |
| **공개 라이브 읽기** | 갤러리 아카이브·뉴스(구글 시트), YouTube | 불필요 | 요청 시 캐시 |
| **Supabase** | 매일 누적되는 작가 언급 signals, 티어 | 기존 env | 크론 07:00 KST |

**핵심**: Supabase가 비어 있어도 화면은 채워진다. 앞의 두 계층만으로 홈·전시·시장·
캘린더가 전부 동작한다.

### 갤러리 뉴스 아카이브

별도 크롤러 파이프라인이 갤러리별로 구글 시트 두 개(서구권 / 국내·아시아)에 매일
쌓는다. 이 사이트는 그 시트를 **인증 없이** CSV로 읽는다 — 링크 공개 시트라 gviz
엔드포인트가 그냥 열린다. 앱스스크립트 다리가 필요 없다.

```
https://docs.google.com/spreadsheets/d/{SHEET_ID}/gviz/tq?tqx=out:csv&sheet={탭이름}
```

gid가 아니라 **탭 이름으로** 읽는 이유: gid를 하드코딩하면 탭이 지워지고 다시
만들어졌을 때 조용히 빈 탭을 읽는다.

갤러리를 추가하려면 `lib/galleries.ts`의 `GALLERIES`에 한 줄 쓰면 된다. 시트에 탭이
먼저 있어야 한다.

카테고리 표기가 갤러리마다 제각각(`solo show` / `개인전` / `Museum Exhibitions`,
White Cube는 아예 지점 이름)이라 `normalizeKind()`가 전시·페어·행사·소식·미디어
다섯 갈래로 정규화한다.

### 경매 인덱스 (시장 축)

`scripts/build_market_index.py`(데이터 워크스페이스에 있다)가 서울옥션·케이옥션
낙찰 기록 24,000여 건을 작가별로 집계해 `data/market/artists.json`을 만든다.

```bash
python3 scripts/build_market_index.py --site /path/to/artrend-site
git add data/market && git commit
```

**성과를 재는 방식.** 낙찰가를 다른 작가의 가격과 비교하지 않는다. 그 롯에 경매사가
매긴 추정가 구간 안에서 어디에 떨어졌는지(`band`, 0=하한 1=상한)만 본다. 국내 시장
전체의 중앙값이 정확히 `0.0`이라 — 즉 하한에 걸려 낙찰되는 게 이 시장의 정상이라 —
0을 넘는다는 사실 자체가 평균 이상이라는 뜻이 된다. `hammer/est_high`로 재면
모두가 0.5 근처라 아무도 구분되지 않고, `hammer/est_low`로 재면 전부 1.0에 뭉친다.

서울옥션은 같은 도록 피드에 샤넬·에르메스 같은 명품 롯을 올리고 브랜드명이 작가명
칸에 들어온다. 이름 기준 블록리스트로 제외한다 — 재료(`leather` 등) 기준으로 거르면
실제 금속·주얼리 작가까지 같이 걸린다.

한국어 이름과 영문 이름을 잇는 사전은 서울옥션 CSV의 `작가명(국문)`/`작가명(영문)`
칼럼 쌍에서 만든다. 언급 추출은 한국어 이름을 뱉고 경매 기록은 영문이라, 이 매핑이
없으면 두 데이터가 영영 만나지 않는다.

### 해외 경매 인덱스

`scripts/build_intl_market_index.py`가 본햄스·크리스티·소더비(Artnet 내보내기)의
파인아트 롯 183,716건을 작가 9,243명으로 집계해 `data/market/intl.json`을 만든다.
국내와 다른 점이 둘 있고, 그 차이가 화면 문구까지 정한다.

**통화가 일곱 가지다.** GBP·USD·EUR·HKD·AUD·CHF·CNY가 섞여 있고 믿을 만한 환산이
없다 — 본햄스가 주는 `estLowGBP`/`estHighGBP`는 74%의 행에서 하한과 상한이 같은 값이라
쓸 수 없다. 그래서 **금액은 절대 합산하지 않고** 작가마다 가장 많이 쓰인 통화로만 적는다.

**가격 정의가 다르다.** 본햄스·소더비는 해머가, 크리스티는 수수료 포함가다. 추정가는
셋 다 해머 기준이라 크리스티 쪽 band가 구조적으로 높다 — 기준선이 **1.25 대 0.167**이다.
그냥 섞었으면 크리스티에 나온 작가가 전부 급상승으로 보였을 것이다. 그래서 band는
자기 basis의 기준선을 뺀 값으로 저장한다. 0이 평균이다.

작업하며 실제로 밟은 함정 셋:

- **세일명 필터에서 크리스티의 "20th Century Day Sale" / "20th/21st Century Art
  Evening Sale"을 빠뜨려** 이우환·김환기·박서보가 통째로 누락됐다. 크리스티는 카테고리
  필드가 없어 세일명으로 거르는데, 최대 현대미술 세일의 이름에 "contemporary"가 들어가지
  않는다.
- **도록의 생몰년 표기**(`PABLO PICASSO (1881-1973)` / `LEE UFAN (B. 1936)` /
  `Lee Ufan (né en 1936)`)를 떼지 않아 같은 작가가 서넛으로 쪼개졌다.
- **추정가 구간이 좁은 롯**(100~110에 800 낙찰)은 band가 수십으로 튄다. 하한 대비 15%도
  안 되는 구간은 아예 빼고, 나머지는 클립한다. 이걸 넣기 전에는 급상승 목록이 전부
  천장값에 붙어 순위가 무의미했다.

### K-artist abroad / Seoul now

`lib/intlMarket.ts`의 `koreanArtistsAbroad()` / `foreignArtistsInSeoul()`이 국내와 해외
인덱스를 잇는다. **어느 한쪽 데이터만으로는 만들 수 없는 화면이다** — 국내 매체는 국내
경매만 다루고 해외 데이터베이스는 영문명만 쓴다. 두 기록을 잇는 열쇠는 서울옥션이
작가명을 국문·영문으로 나란히 싣는다는 사실 하나뿐이다.

한국 작가인지는 **한글 표기와 영문 표기를 모두** 봐야 한다. 한글만 보면(띄어쓰기 없는
2~4음절 + 한국 성씨) 장샤오강·인베이더가 섞여 들어온다. 영문 쪽 첫/마지막 토큰이 한국
성씨의 로마자 표기인지까지 확인한다.

## PWA

홈 화면에 추가하면 주소창 없이 앱처럼 실행된다. `public/manifest.json`이 이름과 아이콘을,
`public/sw.js`가 캐싱과 오프라인 화면을 담당한다.

서비스워커는 **프로덕션 빌드에서만 등록된다.** `npm run dev`에서는 동작하지 않으므로
로컬 확인은 `npm run build && npm run start`로 한다.

캐시 내용을 바꿨을 때는 `public/sw.js`의 `VERSION` 문자열을 올려야 기존 방문자에게 반영된다.

## 뉴스 — 구글 시트 + Apps Script

**사이트는 RSS를 직접 가져오지 않는다.** 구글 시트에 붙인 Apps Script가 6시간마다
피드 30여 곳을 모아 한국어로 번역해 시트에 쌓고, 사이트는 그 시트를 CSV로 읽기만 한다.

이렇게 바꾼 이유:

- **번역이 공짜다.** `LanguageApp.translate`는 Apps Script 내장이라 과금이 없다.
  전에는 Gemini/Claude를 불렀고, 키가 없거나 모델명이 바뀌면 조용히 실패해 해외 탭
  절반이 영어로 남았다.
- **같은 기사를 두 번 번역하지 않는다.** 결과가 시트에 남는다.
- **맥 전원과 무관하다.** 시간 트리거가 구글 서버에서 돈다.
- 요청마다 30여 개 피드를 병렬로 긁던 것이 CSV 두 장 읽기로 줄었다.

### 설치

`news/apps_script/Code_news.gs`를 새 스프레드시트의 Apps Script에 붙여넣고 `setup()`을
한 번 실행하면, 탭 두 개(`국내`/`해외`)와 6시간 트리거가 만들어진다. 시트를 **링크 공개
(뷰어)** 로 바꾼 뒤 시트 ID를 `NEWS_SHEET_ID` 환경변수에 넣는다. 자세한 절차는 그 파일
상단 주석에 있다.

칼럼: `날짜 | 매체 | 제목 | 제목(한국어) | 요약(한국어) | 원문링크`

제목이 이미 한국어면 번역 칸을 비워 둔다 — 호출도 아끼고 원문이 더 정확하다. 화면은
번역이 있으면 그것을, 없으면 원문을 제목으로 쓴다(`displayTitle`).

### 피드 추가

`Code_news.gs`의 `FEEDS`에 한 줄 쓴다. `filter: true`는 종합 문화면용으로, `ART_TERMS`에
걸리는 기사만 통과시키고 `BLOCK_TERMS`에 걸리면 버린다. 미술 전문지는 `false`.

한 매체가 목록을 독점하지 않도록 수집 시 매체당 3건, 화면에서 다시 2건 상한을 둔다.

피드 하나가 죽어도 나머지는 그대로 들어온다(로그만 남는다). Artnet은 봇 차단이 걸려
있어 로컬에서는 403이지만 구글 서버 IP로는 통과할 수 있어 목록에 남겨 뒀다.

**사이트의 `/sources` 페이지는 매체 목록을 코드가 아니라 시트에서 읽는다** — 피드를
늘리면 화면이 저절로 따라온다.

## 매일 오전 7시 갱신

`vercel.json`의 크론이 매일 **22:00 UTC = 07:00 KST**에 `/api/refresh`를 호출하고,
그 시점에 피드 캐시가 비워진다. 그 전까지는 몇 명이 방문하든 같은 기사를 본다.

화면 상단에 "8월 14일 오전 7시 판"이 표시되어, 지금 보는 내용이 언제 기준인지 알 수 있다.

### 배포 전 한 가지 설정

Vercel 프로젝트 → Settings → Environment Variables 에서 `CRON_SECRET`을 추가한다.
값은 아무 긴 무작위 문자열이면 된다. Vercel이 크론 요청에 이 값을 자동으로 실어 보내므로,
외부에서 `/api/refresh`를 함부로 호출하는 것을 막아준다.

설정하지 않아도 동작은 하지만, 누구나 갱신을 유발할 수 있으니 넣어두는 편이 좋다.

### 시각을 바꾸려면

`vercel.json`의 `schedule`은 UTC 기준이다. KST에서 9시간을 빼면 된다.

| 원하는 KST | schedule |
| --- | --- |
| 06:00 | `0 21 * * *` |
| 07:00 | `0 22 * * *` |
| 08:00 | `0 23 * * *` |
| 09:00 | `0 0 * * *` |

바꿀 때는 `lib/edition.ts`의 `CUTOFF_HOUR`도 같은 시각으로 맞춰야 표시가 어긋나지 않는다.

Vercel 무료 플랜에서 크론은 하루 한 번까지이고, 지정 시각에서 최대 한 시간 늦게 실행될 수 있다.
정시 실행이 필요하면 유료 플랜으로 올려야 한다.

## YouTube 연결

키가 없으면 영상 영역만 안내 문구로 바뀌고 나머지 화면은 그대로 동작한다.
키를 잘못 넣어도 마찬가지다. 급하지 않으면 나중에 넣어도 된다.

### 키 발급

1. console.cloud.google.com 접속, 프로젝트 하나 생성
2. API 및 서비스 -> 라이브러리 -> **YouTube Data API v3** 검색 후 사용 설정
3. 사용자 인증 정보 -> 사용자 인증 정보 만들기 -> **API 키**
4. 만들어진 키의 애플리케이션 제한사항은 **없음**, API 제한사항은 **YouTube Data API v3**로 지정

키는 서버에서만 쓰이므로 브라우저에 노출되지 않는다.

### 등록

Vercel -> Settings -> Environment Variables 에 `YOUTUBE_API_KEY`로 추가한 뒤 재배포한다.
로컬은 `.env.example`을 `.env.local`로 복사해 값을 채운다.

### 채널 추가

현재 국내 11곳, 해외 10곳이 연결되어 있다. 대중 해설, 미술관, 페어·비엔날레, 경매사를
고루 섞어 한쪽 성격에 치우치지 않게 했다.

`lib/youtube.ts`의 `CHANNELS`에 채널 ID를 넣는다.

```ts
{ id: "UC로 시작하는 채널 ID", name: "표시할 이름", scope: "kr" }
```

핸들(@이름) 대신 **채널 ID를 쓴다.** 한글 핸들은 URL 인코딩 문제가 생기고,
채널 ID는 `UC`를 `UU`로 바꾸면 업로드 재생목록 ID가 되어 조회 없이 바로 쓸 수 있다.

유튜브도 뉴스와 같이 채널당 상한을 둔다. 일반 영상 2건, 숏츠 3건이다.
채널에서 충분히 모이지 않으면 `QUERIES`의 키워드 검색으로 보충한다.

### 숏츠

숏츠와 일반 영상은 분리해 보여준다. 일반 영상은 16:9 격자, 숏츠는 9:16 가로 스크롤 줄이다.
세로 영상을 16:9 격자에 넣으면 잘리거나 여백이 생겨 화면이 무너진다.

YouTube API는 숏츠 여부를 직접 알려주지 않는다. `videos.list`로 길이를 조회해
`lib/youtube.ts`의 `SHORT_MAX_SECONDS`(기본 100초) 이하면 숏츠로 본다.
숏츠 상한이 3분이라 그보다 짧은 일반 영상이 섞일 수 있고, 반대로 100초를 넘는 숏츠는
일반 영상 쪽에 들어간다. 값을 조절해 취향에 맞추면 된다.

길이 조회는 50개당 1 유닛이라 할당량에 거의 영향이 없다.

숏츠를 아예 빼려면 `VideoGrid.tsx`에서 `state.shorts.length > 0` 블록을 지우면 된다.

### 할당량

기본 할당량은 하루 10,000 유닛이다. 채널 하나당 1 유닛, 길이 조회는 50개당 1 유닛,
키워드 검색만 100 유닛이다. 채널 21곳을 다 합쳐도 하루 250 유닛 정도라 여유가 크다.

## Supabase 연결

작가·전시 데이터를 쌓아두는 곳이다. 뉴스·영상과 달리 이 데이터는
"오늘 것만 보여주고 버리는" 게 아니라 매일 누적해야 티어(ESTABLISHED/RISING/ROOKIE)와
4축 점수가 계산된다.

### 프로젝트 만들기

1. supabase.com 접속, 회원가입
2. New project → 이름은 `artrend`, 리전은 **Northeast Asia (Seoul)** 선택, 비밀번호 설정
3. 생성 완료까지 1~2분 대기

### 스키마 적용

프로젝트 대시보드 → SQL Editor → New query. 아래 두 파일 내용을 순서대로 붙여넣고 실행한다.

1. `supabase/schema.sql` — 테이블, 인덱스, 접근권한(RLS)
2. `supabase/seed_venues.sql` — 기관 가중치 초기값 (국립현대미술관, 국제갤러리 등 40여 곳)

### 키 등록

Settings → API에서 세 값을 확인해 Vercel 환경변수에 등록한다.

| Supabase 화면의 이름 | Vercel 환경변수 이름 | 비고 |
| --- | --- | --- |
| Project URL | `NEXT_PUBLIC_SUPABASE_URL` | |
| anon public | `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 읽기 전용. 브라우저 노출 가능 |
| service_role | `SUPABASE_SERVICE_ROLE_KEY` | **절대 브라우저에 노출 금지.** 크론에서만 쓴다 |

로컬 확인은 `.env.example`을 `.env.local`로 복사해 값을 채운다.

### 연결 확인

배포 후 `/api/status`를 열어본다. `supabase_connection: "ok"`이면 연결된 것이다.
아직 테이블에 데이터가 없으므로 `artists_table_rows: 0`이 정상이다.

이 엔드포인트는 화면 어디에도 연결되어 있지 않다. 진단 전용이다.

### 데이터 모델

```
artists              작가. 국적(nationality)과 활동 장소(venues.country)를 분리해서
                      "한국 작가가 해외에서 뜨는 순간" 같은 교차 신호를 잡을 수 있게 한다
venues                미술관·갤러리·페어. weight가 제도점수의 재료
exhibitions           전시. venue_id, exhibit_type(solo/group/biennale/fair/graduation)
exhibition_artists    전시 ↔ 작가 다대다
signals               4축 이벤트를 전부 여기 한 테이블에 쌓는다
                      (axis: market/institution/discourse/attention)
artist_daily_scores   매일 배치가 signals를 집계해 남기는 스냅샷. 프론트는 이것만 읽는다
```

`signals`를 하나로 합친 이유: 낙찰가든 전시든 유튜브 조회수든 결국
"이 시점에 이 작가에게 이런 일이 있었다"는 같은 모양이다. 축마다 테이블을 나누면
축이 하나 늘 때마다 스키마와 쿼리를 다시 짜야 한다.

## 홈 화면의 대·중·소

정보를 세 층으로 나눠 배치한다. "지금 나오는 게 너무 없다"와 "다 쏟아내지 말고
정돈해서 보여달라"를 동시에 만족시키려면 양이 아니라 위계가 필요했다.

- **대** — 히어로 하나 + 옆에 셋. 오늘 가장 먼저 봐야 할 것. 우선순위는
  ①진행 중이거나 3주 안에 열리는 대형 페어 → ②경매에서 눈에 띈 결과 →
  ③갤러리 아카이브 최신 전시. 페어를 맨 앞에 둔 건 유일하게 "지금 가야 하는 것"이라서다.
- **중** — 트렌딩 작가, 이번 주 키워드, 시장 신호, 전시, 아트 캘린더, 갤러리 소식.
- **소** — 뉴스와 영상 목록.

`/api/home`이 대 영역과 키워드를 한 번에 내려준다.

### 트렌딩과 시장 신호를 갈라놓은 이유

둘 다 "지금 뜨는 작가"지만 재는 게 다르다. 트렌딩은 **활동량**(갤러리 소식 + 언급),
시장 신호는 **경매 성과**다. 한 목록에 섞었더니 국내 스코프에서 경매 급상승 작가가
열 칸을 다 채워 화면이 같은 말을 두 번 했다. `/api/trending`은 경매를 섞지 않고,
상단 스토리 원형만 세 소스를 번갈아 뽑는다.

`lib/tiers.ts`와 `/api/tiers`(ESTABLISHED/RISING/ROOKIE)는 백엔드에 남아있고
시장 축도 이제 실제 값을 받지만, 화면에는 아직 연결되어 있지 않다.

### 아트 행사

`lib/fairs.ts`의 정적 캘린더가 기본이고, `/admin/exhibitions`로 Supabase에 수동
등록한 행사가 있으면 `/api/fairs`가 합쳐서 내려준다. 이름이 겹치면 정적 쪽이 이긴다.
`supabase/migration_002_fair_summary.sql`이 그 수동 입력 경로에 필요하다.

## 방향 전환: 전시 이력 → 언급 트렌드

처음엔 전시 이력(제도점수)으로 작가 티어를 계산하려 했다. 공공API 인증에서 계속
막히기도 했고, 더 근본적으로는 이게 원래 목표와 어긋났다 — 원했던 건 "전시 관리"가
아니라 "언급이 늘고 있는 작가·작품을 보는 트렌드 화면"이었다.

그래서 방향을 바꿨다. **뉴스·영상에서 작가 이름이 언급된 빈도**를 세는 쪽으로.

- `venues`/`exhibitions` 테이블과 `/admin/exhibitions` 화면은 스키마와 코드에 남아있지만
  현재 파이프라인에서 쓰지 않는다. 나중에 필요해지면 다시 쓸 수 있어 지우지 않았다.
- `lib/culture.ts`(공공API 수집 코드)도 마찬가지로 미사용 상태로 남겨둔다.

## 언급 추출 (Claude 기반)

이름이 사람 이름인지, 그중에서도 미술 작가인지 판별하는 건 정규식이나 고정 목록으로는
정확도가 낮다. 그래서 매일 수집된 뉴스·영상 텍스트를 Claude API로 보내 작가 이름만
뽑아낸다. 큐레이터·갤러리스트·컬렉터는 제외하도록 프롬프트에 명시했다.

### 설정

console.anthropic.com에서 API 키를 발급받아 Vercel에 `ANTHROPIC_API_KEY`로 등록한다.
하루 한 번, 텍스트 100여 건을 처리하는 정도라 비용은 미미하다(`claude-haiku-4-5` 사용).

### 동작 방식

`/api/refresh`가 매일 07:00 KST에 다음을 수행한다.

1. 뉴스·영상 캐시 갱신 (기존과 동일)
2. 오늘 수집된 뉴스 제목+요약, 영상 제목을 모아 Claude에 전달
3. 추출된 작가 이름을 `artists` 테이블에 upsert (이미 있으면 재사용)
4. 각 언급을 `signals` 테이블에 기록 — 뉴스는 `axis: discourse`, 영상은 `axis: attention`

추출이 실패해도(키 미설정, API 오류) 뉴스·영상 갱신 자체는 항상 성공한다 — 두 기능이
분리되어 있다.

### 트렌딩 확인

`/api/trending`에서 최근 7일 언급량과 그 전주 대비 증가율을 볼 수 있다.
데이터가 아직 없으면 빈 배열이 정상이다 — 크론이 하루 이상 돌아야 뭔가 쌓인다.

```json
{
  "trending": [
    { "nameKo": "김민정", "mentionsThisWeek": 4, "mentionsLastWeek": 1, "growth": 3 }
  ]
}
```

## 3단계 분류 (전시 이력 없이)

`/api/tiers`가 계산하지만 **현재 화면 어디에도 연결되어 있지 않다** — 홈은 트렌딩
목록과 시장 신호를 쓴다. 나중에 작가 상세의 배지로 쓸 수 있어 남겨뒀다.
`lib/tiers.ts`의 기준(초기 추정값, 조정 가능):

| 티어 | 기준 |
| --- | --- |
| ROOKIE | 첫 언급이 14일 이내이고 명성 확립 표시가 없는 경우 |
| ESTABLISHED | ①명성 확립으로 표시됨, 또는 ②최근 8주 중 3주 이상 언급됨 |
| RISING | 나머지 — 이번 주 언급이 있지만 아직 꾸준하다고 보기엔 이름 |

최근 14일간 언급이 전혀 없는 작가는 목록에서 빠진다.

### "우리가 오늘 처음 봤다" ≠ "신진이다"

처음 버전은 "우리 시스템이 이 이름을 언제 처음 관측했는가"만으로 ROOKIE를 판정했다.
문제는 시스템 자체가 가동한 지 며칠 안 됐다는 점이다 — 그러면 박서보처럼 이미
미술사에 확고히 자리잡은 거장도, 오늘 처음 언급이 잡히는 순간 ROOKIE로 떨어진다.
"우리 관측 기간"과 "실제 세계에서의 인지도"를 혼동한 것이다.

그래서 `lib/extract.ts`의 추출 프롬프트에 fame 판단을 추가했다. 새 작가 이름을 뽑을 때
Claude에게 "이미 미술사에 기록됐거나 주요 기관 소장·개인전 이력이 있는 등 명성이
확고한지"를 같이 판단시킨다. 확립된 것으로 판단되면 그 작가는 `artists.tier_locked =
true`로 즉시 ESTABLISHED에 고정된다 — 이후 언급 빈도나 관측 기간과 무관하게 이 분류가
유지된다. 애매하면 반드시 "unknown"을 선택하도록 프롬프트에 명시해, 과잉 판정보다
누락을 택하게 했다.

이 판단은 신규 작가 생성 시점에 한 번만 이루어진다. `tier_locked`가 걸린 작가는
이후 `computeTiers()`에서 관측 기간 로직을 아예 건너뛴다.

### 여전히 남은 한계

- fame 판단은 Claude의 사전 지식에 의존한다. 국내에서는 유명하지만 훈련 데이터에
  약하게 반영된 작가는 여전히 "unknown"으로 시작해, 8주 관측을 거쳐야 ESTABLISHED로
  올라간다. 지연은 있어도 방향은 안전한 쪽(누락)이다.
- `signals`에 scope 컬럼이 없다. 국내/해외 구분은 그 작가가 갤러리 명단이나 경매
  인덱스 어느 쪽에 있는지로 역추적한다(`/api/trending`). 둘 다 없으면 해외로 본다 —
  국내 작가는 거의 언제나 둘 중 하나에는 걸리기 때문이다. 정공법은 추출 시점에
  scope를 같이 저장하는 것이고, 아직 안 했다.

**2026-08-14** — Next.js에서 CVSS 10.0짜리 심각한 원격코드실행 취약점(CVE-2025-66478,

이 사이에 12월·5월 두 차례 추가 보안 릴리스가 더 있었고, 이번에 전부 반영했다.

**앞으로 배포할 때마다** `npm install` 결과에 `deprecated` 경고나 `npm audit`에 high 이상이

## 설계 원칙

- **합산 점수를 만들지 않는다.** 네 축을 각각 보여주고 사용자가 축을 골라 정렬한다. 하나로 합치면 이미 검증된 작가가 영구히 상단을 차지한다.
- **세 구간을 동등하게 노출한다.** ESTABLISHED / RISING / ROOKIE를 가로로 나란히 둔다. 신진을 하단에 두면 열람되지 않는다.
- **등락 색을 쓰지 않는다.** 가격 상승을 빨강으로 칠하는 순간 투기 도구가 된다.
- **작품 이미지는 저작권 확인 후에만 게재한다.** 초기 시각 요소는 영상 썸네일과 사용 허가된 보도자료 이미지로 구성한다.

## 비용 — 무엇이 공짜고 무엇이 돈이 나가는가

화면은 거의 전부 API 호출 없이 돈다. 갤러리 전시·뉴스·트렌딩·스토리·키워드·경매
데이터·시장 페이지·페어 캘린더·유튜브·위키 사진이 모두 무료다. `ANTHROPIC_API_KEY`를
아예 빼도 사이트는 정상 동작한다 — 챗봇만 사라진다.

Claude를 부르는 곳은 둘뿐이다.

| 기능 | 언제 도는가 | 대략 |
| --- | --- | --- |
| `AI_EXTRACT` 작가 이름 추출 | 크론, 하루 1회 | 월 ~500원 |
| `AI_ASK` 챗봇 | **질문할 때마다** | 1건당 40~90원 |

원래 여기 있던 셋이 사라진 경위는 그대로 기록해 둔다:

- **번역·국가태깅** → Apps Script의 `LanguageApp`으로 옮겼다. 내장 함수라 공짜이고,
  결과가 시트에 남아 같은 기사를 두 번 번역하지 않는다.
- **작가 요약** → `lib/why.ts`가 순위 계산에 쓴 수를 그대로 문장으로 조립한다.
  공짜인 것보다 중요한 건 **화면에 적힌 근거와 실제 계산 근거가 항상 같다**는 점이다.
  모델이 기사 제목을 읽고 쓰면 둘이 어긋날 수 있었다.

`/api/ask`는 공개 엔드포인트라 상한이 없다. IP당 시간당 호출 제한(`ASK_PER_HOUR`,
기본 10)이 걸려 있지만 서버리스 인스턴스마다 메모리가 따로 놀아 완벽한 방어가 아니다.
**진짜 상한은 Anthropic Console의 지출 한도로 걸어야 한다.**

## 챗봇

`/api/ask`가 Claude에 이 사이트의 데이터를 도구로 물려서 답한다. "아트바젤 언제
열려?"는 페어 캘린더에서, 작가 질문은 경매 인덱스와 갤러리 아카이브에서 답하고,
없는 건 Anthropic 서버측 웹 검색으로 보완한다. 어느 쪽에서 온 정보인지 답변에
밝히게 프롬프트에 못 박아 뒀다.

도구는 `lib/ask.ts`의 `TOOLS`에 있다. 새 도구를 붙이려면 `run` 함수와 스키마를
한 항목으로 추가하면 된다 — 라우트는 이름으로 찾아 실행한다.

**기본은 꺼짐이다.** `AI_ASK=on`을 넣어야 켜지고, 꺼져 있으면 버튼 자체가 그려지지
않는다 — 눌러도 "꺼져 있습니다"만 뜨는 버튼을 화면에 둘 이유가 없다. 화면은
`GET /api/ask`로 켜짐 여부를 한 번 확인한다.

모델은 `ASK_MODEL`로 바꾼다. 기본 `claude-sonnet-5`이고 `claude-haiku-4-5`로 내리면
1/3 가격이지만, 도구 5개와 웹 검색을 함께 다루는 작업이라 답이 얕아질 수 있다.
`ASK_WEB_SEARCH=off`면 웹 검색 없이 사이트 데이터로만 답한다 — 검색은 토큰과 별개로
1,000회당 $10이 붙는다.

## 원칙

- **합산 점수를 만들지 않는다.** 네 축을 각각 보여주고 사용자가 축을 골라 정렬한다.
  하나로 합치면 이미 검증된 작가가 영구히 상단을 차지한다.
- **등락 색을 쓰지 않는다.** 가격 상승을 빨강으로 칠하는 순간 투기 도구가 된다.
  증감은 부호와 막대 길이로만 표시한다.
- **가격은 그 작품의 추정가하고만 비교한다.** 다른 작가의 가격과 견주지 않는다.
- **가짜인 척하지 않는다.** 목업을 진짜처럼 두느니 빈 상태를 정직하게 쓴다.
  날짜가 미정인 페어는 추정하지 않고 "미정"으로 둔다.
- **작품 이미지는 저작권 확인 후에만 게재한다.** 인물사진은 위키피디아 CC 이미지,
  나머지 시각 요소는 영상 썸네일이다.
