# ARTREND — Product Requirements Document

**버전**: v0.1 draft · **작성일**: 2026-08-19 · **상태**: 개발 진행 중 (백엔드 파이프라인 구축 단계)

---

## 1. 개요

ARTREND는 국내외 미술 동향을 한눈에 보여주는 웹/PWA 대시보드다. 주식 트렌드 앱의
UI 문법(랭킹, 필터, 실시간성)을 빌리되, 가격 중심 언어(등락 컬러, 시가총액 순위)는
의도적으로 배제한다. 목적은 "누가 지금 얼마에 팔리는가"가 아니라 **"누가 지금
언급되고 있는가"** — 즉 담론과 관심의 흐름을 읽는 것이다.

### 1.1 핵심 문제의식

기존 미술 매체·시장 데이터는 두 가지로 쏠려 있다.

1. **이미 유명한 작가 중심** — 경매 낙찰가, 갤러리 명성 등 시장 지표는 후행적이라
   이미 확고히 자리잡은 작가만 계속 상위에 노출된다.
2. **파편화된 소스** — 뉴스, 유튜브, SNS, 경매 정보가 각자 다른 채널에 흩어져 있어
   종합적인 흐름을 파악하기 어렵다.

ARTREND는 이 둘을 해결한다: **다양한 소스에서 언급 빈도를 자동 수집**하고,
**신진·중견·거장을 동등한 화면 비중으로 노출**해 시장 지표가 아직 반영하지 못한
"떠오르는 신호"를 잡아낸다.

### 1.2 대상 사용자

- 미술 시장 동향을 빠르게 훑고 싶은 컬렉터·업계 관계자
- 신진 작가를 발굴하고 싶은 갤러리스트·큐레이터
- 국내외 미술 담론을 캐주얼하게 따라가고 싶은 일반 애호가

## 2. 설계 원칙

빌드 과정에서 여러 차례 방향 수정을 거쳐 확정된 원칙들이다. 이후 기능 추가 시
이 원칙과 충돌하면 원칙이 우선한다.

| 원칙 | 이유 |
| --- | --- |
| **합산 점수를 만들지 않는다** | 축을 하나로 합치면 이미 유명한 작가가 항상 상단을 차지한다. 축을 나눠 보여주고 사용자가 고른다. |
| **ESTABLISHED / RISING / ROOKIE를 동등한 화면 비중으로 노출** | 신진을 하단에 두면 아무도 안 본다. 가로 3분할로 처음부터 동등하게. |
| **등락 색을 쓰지 않는다** | 가격 상승을 빨강으로 칠하는 순간 투기 도구처럼 보인다. |
| **"우리가 언제 처음 봤는가" ≠ "실제로 얼마나 유명한가"** | 시스템이 방금 가동을 시작했다는 이유로 거장이 신진으로 오분류되면 안 된다. (아래 6.3 참고) |
| **작동하지 않는 UI를 두지 않는다** | 클릭해도 아무 일 안 일어나는 탭/버튼은 신뢰를 깎는다. 준비 안 됐으면 비활성화 표시. |
| **실패해도 조용히 무너지지 않는다** | 외부 API 하나가 막혀도 나머지 기능은 정상 작동해야 한다. |
| **가짜 데이터로 화면을 채우지 않는다** | 실데이터가 없으면 "없다"고 보여준다. 목업을 실데이터처럼 위장하지 않는다. |

## 3. 개발 히스토리 요약 (의사결정 로그)

향후 협업자가 "왜 이렇게 만들었는지"를 다시 묻지 않도록 주요 피벗을 기록한다.

1. **전시 이력 기반 "제도점수" 시도 → 폐기**
   문화포털 공공API(data.go.kr)로 전시 데이터를 모아 기관 가중치로 작가 등급을
   매기려 했으나, API 인증이 계속 실패했고(엔드포인트 변경, 서비스키 활성화 지연),
   더 근본적으로 이것이 원래 목표("언급 트렌드")와 어긋난다는 점을 확인해 폐기했다.
   관련 코드(`lib/culture.ts`, `venues`/`exhibitions` 테이블, `/admin/exhibitions`)는
   남아있지만 현재 파이프라인에서 사용하지 않는다.

2. **언급량 기반으로 전환**
   뉴스·유튜브 텍스트에서 작가 이름을 추출해 언급 빈도로 트렌드를 계산하는
   방식으로 전환. 이름 추출은 정규식이 아니라 Claude API로 처리한다(문맥 판단이
   필요해서).

3. **"오늘 처음 봤다 = 신진이다" 오류 수정**
   초기 티어 로직은 "우리 시스템이 이 이름을 언제 처음 관측했는가"만으로
   ROOKIE를 판정했는데, 시스템이 막 가동을 시작한 상태라 박서보 같은 거장도
   ROOKIE로 분류되는 문제가 발견됨. 이름 추출 시점에 Claude가 "이미 명성이
   확립된 인물인지"를 같이 판단하도록 수정해, 확립된 경우 즉시 ESTABLISHED로
   고정(`tier_locked`)하도록 변경.

4. **가짜 탭 제거**
   상단 네비게이션에 5개 탭이 있었으나 "트렌드" 외에는 클릭해도 내용이 바뀌지
   않는 장식이었음이 지적되어, 실제로 작동하는 "소스" 탭을 추가하고 나머지는
   "준비중"으로 명시적으로 비활성화.

5. **RSS 없는 국가 대응**
   일본·프랑스 등은 현지 매체가 RSS를 거의 제공하지 않아, Google 뉴스 언어별
   검색 RSS로 우회 수집하고 Gemini API로 한국어 번역하는 파이프라인을 추가.
   (번역 연결에 이슈 있어 디버깅 진행 중 — 11장 참고)

```
[국내 | 해외]                      ← 전역 스코프 토글
  트렌드(홈) | 소스 | 작가* | 전시* | 시장* | 캘린더*     (*준비중, 비활성화)

홈 화면 구성:
  이번 주 키워드          (목업 — 실데이터 미연결)
  작가 동향 (3티어 그리드)  (실데이터 — /api/tiers)
  K-artist abroad / Seoul now  (목업 — 실데이터 미연결)
  영상 (YouTube, 검색·채널필터·정렬 가능)

  전시 수동 입력 폼 (현재 파이프라인에서 미사용, 보류 상태로 유지)
```

## 6. 핵심 기능 명세

### 6.1 언급 추출 파이프라인

**목적**: 뉴스·영상 텍스트에서 미술 작가로 언급된 인물만 자동 추출.

**방식**: Claude API(`claude-haiku-4-5`)에 당일 수집된 뉴스 제목+요약, 영상
제목을 배치로 전달. 큐레이터·갤러리스트·컬렉터는 제외하도록 프롬프트에 명시.

**저장**: 추출된 이름은 `artists` 테이블에 upsert. 언급 1건마다 `signals`
테이블에 행 하나 기록 — 뉴스는 `axis: discourse`, 영상은 `axis: attention`.

**실행 주기**: 매일 07:00 KST, `/api/refresh`(Vercel Cron)가 호출.

**실패 처리**: 추출 실패해도 뉴스·영상 갱신 자체는 항상 성공 (기능 분리).

### 6.2 3단계 분류 (ESTABLISHED / RISING / ROOKIE)

| 티어 | 판정 기준 |
| --- | --- |
| ESTABLISHED | ① 명성 확립으로 표시됨(6.3 참고), 또는 ② 최근 8주 중 3주 이상 언급 |
| RISING | 나머지 — 이번 주 언급이 있으나 꾸준하다고 보기엔 이름 |
| ROOKIE | 첫 언급이 14일 이내이고 명성 확립 표시가 없는 경우 |

최근 14일간 언급이 전혀 없는 작가는 목록에서 제외. 국내/해외 스코프 구분 없이
통합 목록으로 노출(현재 `signals`에 scope 컬럼 없음 — 8장 향후 과제 참고).

### 6.3 명성 확립 판정 ("우리가 처음 봤다" 오류 방지)

신규 작가 생성 시점에 Claude가 "이미 미술사에 기록됐거나 주요 기관 소장·개인전
이력이 있는 등 명성이 확고한지"를 함께 판단. 확립된 것으로 판단되면
`artists.tier_locked = true`로 즉시 ESTABLISHED 고정 — 이후 관측 기간과 무관하게
유지. 애매하면 반드시 "unknown" 선택(과잉 판정보다 누락 우선).

### 6.4 해외 뉴스 국가 태깅 + RSS 우회 번역

- 해외 기사는 Claude가 본문 맥락으로 국가를 판정해 태깅(`lib/geo.ts`). 완벽한
  지오코딩이 아니므로 불명확하면 "기타/글로벌".
- 일본·프랑스는 원본 RSS가 없어 Google 뉴스 언어별 검색으로 원문을 수집하고
  Gemini API로 한국어 번역(`lib/googlenews.ts`, `lib/translate.ts`). 번역
  실패 시 원문 그대로 노출(빈 화면보다 원문이 낫다는 판단).
- 해외 뉴스 패널에는 실제로 태깅된 국가만 필터 칩으로 노출.

### 6.5 PWA

`manifest.json` + 서비스워커로 홈 화면 추가 시 앱처럼 실행. 오프라인 폴백 페이지
제공. API 응답은 서비스워커 캐시에서 제외(항상 최신 데이터 우선).

### 6.6 소스 투명성 (`/sources`)

연결된 모든 뉴스 매체·유튜브 채널을 이름+링크로 나열. "정말 연결되어 있는가"를
사용자가 직접 검증할 수 있게 하기 위한 화면 — 채팅으로만 전달되던 정보를
신뢰 가능한 형태로 노출.

## 7. 데이터 모델

```
artists               작가. nationality(국적)와 venues.country(활동 장소)를
                       분리해 "한국 작가가 해외에서 뜨는 순간" 같은 교차 신호를
                       잡을 수 있게 설계(현재 미사용 — 8장 참고).
                       tier / tier_locked로 명성 확립 여부 고정.
venues                미술관·갤러리·페어 (현재 파이프라인 미사용, 보류)
exhibitions           전시 (현재 파이프라인 미사용, 보류)
exhibition_artists    전시 ↔ 작가 다대다 (현재 파이프라인 미사용, 보류)
signals               4축(market/institution/discourse/attention) 이벤트를
                       전부 이 테이블 하나에 쌓는다. 현재는 discourse(뉴스)와
                       attention(영상)만 채워짐 — market/institution은 설계는
                       되어 있으나 데이터 소스 미연결.
artist_daily_scores    일별 스냅샷 (현재 미사용 — /api/tiers가 signals를
                       요청 시점에 직접 집계하는 방식으로 대체 운영 중)
```

**왜 `signals` 테이블 하나로 통합했는가**: 낙찰가든 유튜브 조회수든 전시
이력이든 "이 시점에 이 작가에게 이런 일이 있었다"는 동일한 형태의 사실이다.
축이 늘어날 때마다 테이블을 새로 만들지 않아도 되게 설계했다.

## 8. 알려진 한계 · 향후 과제

### P0 — 진행 중 이슈
- [ ] **Gemini 번역 미작동** — Vercel에 Google API 키를 등록했으나 번역이
      실행되지 않는 문제 디버깅 중. 유력 원인: (1) Google Cloud 콘솔에서
      Generative Language API 미활성화, (2) 키 권한/API 제한 설정, (3) 모델명
      변경(`gemini-2.0-flash` 가용성). 원문 폴백은 정상 작동(빈 화면 방지).

### P1 — 설계는 됐으나 실행 안 함
- [ ] `/api/tiers`·`/api/trending` 데이터를 실제 배포 환경에서 검증 (현재
      로컬에서 키 없이 빈 상태만 확인함)
- [ ] 시장(market)·제도(institution) 축 데이터 소스 확보 — 현재 0으로 고정
- [ ] 국내/해외 스코프별 트렌딩 분리 (signals에 scope 컬럼 필요)
- [ ] 이번 주 키워드, K-artist abroad/Seoul now 섹션 — 여전히 목업 데이터

### P2 — 보류
- [ ] 문화포털 공공API 재시도 또는 개별 기관 RSS
- [ ] 경매사이트(케이옥션·서울옥션) 언급 소스 추가
- [ ] 조각투자 플랫폼(테사·소투) 데이터 — 선행지표로 유효하나 미착수
- [ ] 독일·중국 등 추가 국가 RSS 우회 (프랑스·일본과 동일 패턴으로 확장 가능)
- [ ] 페어·어워드 캘린더, 작가 상세 페이지

### 구조적 한계 (설계상 트레이드오프, "버그"는 아님)
- 명성 판정은 Claude의 사전 지식에 의존 — 국내에서는 유명하나 학습 데이터에
  약하게 반영된 작가는 "unknown"으로 시작해 8주 관측을 거쳐야 ESTABLISHED로
  올라감 (지연은 있어도 방향은 안전).
- 해외 기사 국가 태깅은 본문 맥락 추론이라 완벽하지 않음.

## 9. 비기능 요구사항

| 항목 | 기준 |
| --- | --- |
| 배포 | GitHub → Vercel 자동 배포, 별도 서버 불필요 |
| 데이터 갱신 | 매일 07:00 KST 1회 (Vercel Cron, 무료 플랜 기준 최대 1시간 지연 가능) |
| 장애 격리 | 외부 소스/API 하나 실패해도 나머지 기능 정상 — 전 구간에 걸쳐 try/catch + 폴백 UI 적용 |

| 저작권 | 뉴스는 제목+요약(130자 컷)+원문 링크만. 본문 재게시 없음 |
| 접근성 | PWA 오프라인 폴백, 다크모드 대응, 키보드 포커스 처리 |

## 10. 성공 지표 (제안 — 확정 필요)

현재 사용자 지표 수집 체계는 없음. 아래는 다음 단계에서 논의가 필요한 제안이다.

- **데이터 신뢰도**: `/api/tiers` 결과 중 상식적으로 맞는 분류 비율 (예: 명백한
  거장이 ROOKIE로 잘못 분류되는 사례 0건)
- **커버리지**: 하루 평균 신규 추출 작가 수, 소스별 기여도 분포(특정 소스 편중 방지)
- **번역 성공률**: 일본/프랑스 기사 중 한국어 번역 성공 비율
